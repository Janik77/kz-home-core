# Редактирование и безопасные копии определений

Новая схема `0018_scene_drafts` добавляет только `scenes.is_draft NOT NULL DEFAULT false`.
Существующие сцены не меняют статус. Это программный кандидат, не обновление постоянного стенда.

## HTTP-контракт

- `GET /scenes` и `/scenes/{id}` возвращают `is_draft: boolean`. Неизвестные поля/типы действий сохраняются в чтении; редактор должен показывать их только для чтения.
- `PATCH /scenes/{id}` использует существующие `name`, `actions`, `expected_revision`. Успех увеличивает revision, включая no-op; устаревший токен даёт `409 definition_revision_conflict`. Сохранение не запускает сцену. Неизвестные ограничения нельзя отбросить даже при переименовании.
- `POST /scenes/{source_id}/duplicate` и `/automations/{source_id}/duplicate`: строго `{id, name, expected_revision}`. Возвращают `201` и обычный read DTO с revision=1. Только тот же дом; права read+manage, актуальная версия источника проверяются под блокировкой в одной транзакции.
- Новая сцена-копия всегда `is_draft=true`. Новое правило-копия всегда `enabled=false`, `authorized_by=null`; состояние порогов/расписания и история запусков не копируются. Редактирование отключённой копии не выдаёт разрешение на исполнение. Его выдаёт отдельное явное включение.
- `id` должен оставаться одним и тем же при неопределённом исходе запроса. Повтор или любое совпадение ID возвращает `409`, никогда не перезаписывает объект. Не следует считать одинаковое содержание доказательством успешного прошлого запроса. Можно прочитать объект и явно решить дальнейшее действие.
- `POST /scenes/{id}/activate`: строго `{expected_revision}`; `200` с `is_draft=false` и revision+1. Уже активная сцена даёт `409`; неверная версия `409 definition_revision_conflict`; неподдерживаемый план `422`. Это НЕ запуск.
- Активация проверяет 1..16 шагов, существующие ограничения durable_wait, Boolean on/off и capability on_off реле в том же доме. Не требует online, текущего значения или разрешения на команду. Эти проверки отдельно выполняются при запуске.
- `is_draft` нельзя записывать через обычные create/PATCH. Обратного active→draft перехода нет. Обычное создание сохраняет прежнюю семантику active (false).
- Любой новый запуск черновика, включая legacy, manual и server, даёт `409 code=scene_draft`. Повтор чтения уже существующих receipts остаётся правдивым; перед новой отправкой статус проверяется снова, в том числе на commit/publish и возобновлении ожидания.

Не копируются command IDs, run IDs, idempotency keys, полномочия, watermark/latch и cursor. Сохранение, копирование и активация не создают команд или запусков. История источника и прежние снимки действий не редактируются. Старые delay не превращаются в durable_wait.

Downgrade запрещён при любом черновике: удаление флага сделало бы его исполнимым. Для обновления постоянного профиля необходима отдельная согласованная интеграционная версия и проверенный backup→новая копия→verify; привязки профиля вручную не меняются.
