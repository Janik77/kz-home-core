# Экспериментальный перенос программного профиля schema0018
Этот режим предназначен для проверяемой копии программного профиля. Он не обновляет рабочую Windows-установку на месте, не переносит профиль 51775 и не даёт доступа к реальным устройствам.
 
**Источник.** Core #60 `80770e8a3f59d0bd7fb825345f0ca7589dd26f23` и Web #33 `36515bdcb003e875108dd722febe5c969825f304`, схема `0018_scene_drafts`. Записанный в исходном профиле runtime Core `1a43ecba1cd07dd231f313fcd42d4d4276e13967` отличается от коммита launcher #60: так была закреплена предыдущая версия.
 
**Назначение.** Core runtime #61 `3cfec75067e4da4a7950de1fb4877e47e346be9b` + отдельный точный Web #34, закреплённый в `CORE61_WEB_SHA` и в CI. Ветка инструмента не является новым runtime SHA. Действующие профили не переключаются на него автоматически.
 
1. Остановите только штатный процесс исходного программного стенда. Убедитесь, что останавливается именно нужный профиль. На его закреплённом исходном Core создайте проверенный format 2 backup штатной командой `backup` в новый приватный каталог, не читайте и не раскрывайте конфиг. Не менять старый профиль или backup вручную.
2. После успешного backup используйте проверенный checkout инструмента с внутри уже доступным Git-объектом полного SHA #60, и чистый точный Web #34 с зависимостями. Дополнительная папка с исходным Core не нужна. В обычном Linux/WSL, с разрешённым локальным Docker context и существующим подготовленным Python, выполните:
 
   ```bash
   python -B tools/durable_software.py upgrade --release core61-web34 \
     --state /absolute/private/new-profile \
     --backup /absolute/private/verified-backup \
     --source-commit 80770e8a3f59d0bd7fb825345f0ca7589dd26f23 \
     --web-root /absolute/existing/kz-home-web
   ```
 
   `new-profile` должен отсутствовать и получить новые owner, идентификатор базы и отдельный loopback-порт. Ветка не переназначает старый URL. Восстановление архива идёт в пустую проверяемую БД, для равной версии 0018 старый Alembic upgrade не вызывается. Контрольные суммы файлов и полный снимок данных проверяются до активации. Сохраняются дом, комнаты, избранное, сцены, журнал, истории и квитанции. В копии отменяются только отложенные продолжения ожидающих сцен, проверенные политикой восстановления; старый профиль не изменяется. Не использовать непроверенные/чужие архивы.
3. Новый профиль запускается той же командой `start --release core61-web34` с новыми `--state` и `--web-root`. Проверьте в браузере название дома, комнаты, избранное, сценарии и журнал. Проверьте отсутствие повторной команды при старте, затем в отдельном тесте сделайте программный ON/OFF с ACK. Сбой синхронизации системного и монотонного времени по-прежнему запрещает команды; не изменяйте этот порог.
 
**Откат.** Остановите новую копию обычным способом и восстановите прежнюю проверенную пару исходников, штатно запустив неизменённый исходный профиль на его старом порту. Не копировать данные новой версии назад на месте и не удалять профили. Любой частично созданный каталог без `initialized` сохранять для диагностики, но не запускать.
 
**Граница CI.** Два Workflow с пометкой historical используют точный Core #60 и показывают только историческую совместимость, не проверяют runtime #61. Отдельный Workflow `Reviewed schema0018 software profile upgrade` проверяет новый пакет на собственных изолированных PostgreSQL и TLS MQTT. Он не подменяет приёмку существующего профиля Windows, её состояния часов или физического ESP32.
